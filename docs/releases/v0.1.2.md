# VRI-Framework v0.1.2

This release improves first-load texture encoding and reduces duplicate asset
cache data while keeping CPU encoding as the default.

- Encode BC7 directly using the fast `bc7e` SIMD encoder, with SSE2/AVX2 runtime
  dispatch on desktop x86-64 and a portable CPU encoder on other architectures.
  Block batches use multiple CPU threads and avoid the UASTC intermediate.
- Cache generated tangents and content-addressed BC7 textures/mips in the platform
  user cache directory. Source geometry and materials are read from the model;
  texture cache hits skip decoding, mip generation and compression.
- Process cold glTF image imports one image at a time, reducing peak decoded
  texture memory. Validate cache checksums and publish entries atomically.
- Add cache counters, regression tests and optional cache/encoder benchmark tools.

## Migration

`LoadModelCached` now defaults to `AssetCacheMode::Derived`. Set
`AssetCacheMode::FullMesh` to retain the previous whole-mesh cache behavior;
`cachePath` applies to that mode. `AssetCacheOptions::directory` selects the new
shared cache root. `WriteBakedMesh` and `ReadBakedMesh` remain available.

Old `.vrfcache` files are not automatically deleted. After validating the new
cache, callers may remove their old files. The shared cache has no automatic
size limit. Encoder recipes distinguish SIMD, portable and uncompressed entries.

BC7 is lossy and the new encoder changes encoded pixels. Recreate both sides of
image-quality comparisons using the same framework version and encoder recipe.
No OpenCL or GPU encoder is enabled by this release.

See [asset-cache documentation](../asset_cache.md) for options and local
performance/size measurements.
